From a text to a Pons launch.

No X API. The sender supplies the token metadata directly by SMS. The backend resolves Pons contract parameters at confirmation time and talks to Robinhood Chain through the public RPC.

Quickstart

The project ships in dry-run mode. Deploy it first, connect Redis, then use the built-in browser tester before connecting a phone line.

EXECUTION_MODE=dry-run ENABLE_ONCHAIN_LAUNCH=false ENABLE_WEB_TESTER=true

Open /test, text LAUNCH, and complete the whole conversation. The web tester can never broadcast because the endpoint forces dry-run mode server-side.

The SMS conversation

The backend asks for the creator-controlled inputs Pons v2 accepts:

LAUNCH 1/11 Token name? 2/11 Ticker? 3/11 Description? 4/11 Logo URL / ipfs:// URI? 5/11 Website? (SKIP allowed) 6/11 X / Twitter URL? (SKIP allowed) 7/11 Telegram URL? (SKIP allowed) 8/11 Discord URL? (SKIP allowed) 9/11 Farcaster URL? (SKIP allowed) 10/11 Creator fee wallet? 11/11 Creator tax + buyback? Example: 1%, YES CONFIRM

The backend handles the technical launch fields automatically: native ETH pair, enabled launch config, economics pin, launch fee, a fresh 32-byte CREATE2 salt and the current protocol creator-tax cap.

Architecture

Phone ↓ SMS HushSMS carrier line ↓ signed webhook POST /api/sms ↓ Upstash Redis conversation state ↓ CONFIRM Robinhood public RPC ↓ Pons v2 factory ↓ TokenLaunched event ↓ HushSMS REST reply → Phone

No X service and no third-party RPC key are required.

Connect HushSMS

  1. Buy a HushSMS mobile line using crypto.
  2. In the HushSMS panel, enable the inbound webhook and point it to https://YOUR-DOMAIN.com/api/sms.
  3. Copy the line ID, line bearer token and webhook signing secret into Vercel environment variables.
  4. Set PUBLIC_PHONE_NUMBER and PUBLIC_PHONE_DISPLAY. The site reads these at runtime from /api/config, so no code edit is required.
PUBLIC_PHONE_NUMBER=+381... PUBLIC_PHONE_DISPLAY=+381 ... HUSHSMS_LINE_ID=ln_... HUSHSMS_LINE_TOKEN=hs_live_... HUSHSMS_WEBHOOK_SECRET=... HUSHSMS_VALIDATE_SIGNATURE=true
Provider API note. The integration sends replies to HushSMS at POST /v1/lines/{lineId}/messages with the line bearer token. Keep the line token server-side only.

Test with a non-US number

You do not need a US SIM to test. HushSMS lists carrier numbers across Europe, including Serbia (+381). A practical test from Kosovo is:

Your phone: +383 ... HushSMS test line: +381 ... Webhook: https://YOUR-DOMAIN.com/api/sms Mode: dry-run

Send LAUNCH from your +383 number to the +381 line. You are testing the actual international carrier → HushSMS → webhook → HushSMS reply loop while the onchain executor remains disabled. Your mobile carrier may charge for an international SMS.

You can later replace the public number with a US HushSMS line by changing only the Vercel environment values.

Pons v2 + Robinhood Chain

Chain ID 4663 RPC https://rpc.mainnet.chain.robinhood.com Factory 0x7eD598BcEf8bd9Edd8C97A195C6d13f40801EC7e Pair 0x0000000000000000000000000000000000000000 (native ETH)

At confirmation, the executor reads the current enabled launch config, launchFee(), maxCreatorTaxBps(), previewLaunchEconomics() and canLaunch(launcher). It then simulates the exact launchToken call before signing.

Current Pons limitation: v2 public launches are currently closed according to Pons documentation. That restriction is enforced onchain. This project cannot and does not bypass it; the configured launcher wallet must pass canLaunch() before a real launch succeeds.

Turn on real launches

Do this only after the SMS flow works in dry-run and the dedicated launcher wallet passes the Pons gate.

  1. Create a new dedicated EVM wallet just for this service.
  2. Fund it with a small amount of ETH on Robinhood Chain for launch fees + gas.
  3. Add the private key as a Vercel secret.
  4. Verify /api/status reports the expected factory, config and launcher gate.
  5. Flip both execution switches:
LAUNCHER_PRIVATE_KEY=0x... EXECUTION_MODE=mainnet ENABLE_ONCHAIN_LAUNCH=true

The two-switch model prevents a mistaken environment change from broadcasting by itself.

Security checklist

  • Use Upstash Redis in production; in-memory state is only a local fallback.
  • Keep HushSMS webhook signature verification enabled.
  • Use a dedicated low-balance launcher wallet, never a treasury wallet.
  • Keep dry-run enabled until the carrier loop is proven end to end.
  • The webhook deduplicates inbound events so a provider retry does not advance a conversation twice.
  • The exact Pons call is simulated before broadcast and economics are pinned immediately before execution.
