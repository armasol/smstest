Launch from the message thread.

LAUNCH/SMS turns a text message into a reviewable token draft and, after explicit confirmation, an onchain launch on Robinhood Chain.

Quickstart

Text the public US number using this format:

LAUNCH @orbitlabs $ORBIT

The service reads the public X profile, builds a draft, sends the exact token name and ticker back to the same number, and waits for confirmation.

READY TO LAUNCH Orbit Labs · $ORBIT @orbitlabs Robinhood Chain · ETH pair Reply YES to deploy.

Command format

Start

LAUNCH @handle $TICKER LAUNCH https://x.com/handle $TICKER

The ticker is optional. If omitted, a clean uppercase ticker is derived from the X handle. Tickers are limited to 10 alphanumeric characters.

Confirm / cancel

YES CONFIRM LAUNCH IT CANCEL NO

Pending drafts expire after 15 minutes.

Launch flow

  1. Twilio receives the inbound SMS and sends it to /api/sms.
  2. The command parser extracts the X handle and requested ticker.
  3. The X API supplies public profile metadata.
  4. The pending draft is stored with a 15-minute TTL.
  5. A reply of YES checks sender authorization and live Pons launch conditions.
  6. The launcher pins current economics, pays the current launch fee, and calls launchToken.
  7. The TokenLaunched factory event is parsed and the token address is returned by SMS.
No fake success state. If the contract gate, configuration, RPC, sponsor wallet, or transaction fails, the user receives an error and the pending draft remains available for retry.

Deployment

This repository is Vercel-ready. Import it as a Vercel project, add the environment variables from .env.example, then configure your Twilio number’s incoming message webhook to:

POST https://YOUR-DOMAIN.com/api/sms

Set the public site number in index.html and assets/app.js after buying the Twilio number. The included +1 (555) 013-7117 is a safe US placeholder, not a live carrier number.

Required environment variables

TWILIO_AUTH_TOKEN= X_BEARER_TOKEN= UPSTASH_REDIS_REST_URL= UPSTASH_REDIS_REST_TOKEN= LAUNCHER_PRIVATE_KEY=0x... ALLOWED_PHONE_NUMBERS=+1...

Security

The deployment wallet pays the onchain launch fee, so the default configuration is intentionally allowlisted. Do not enable public sponsored launches until you have abuse controls, billing, rate limits and a clear custody model.

Twilio webhook signature validation is enabled by default. Pending state is keyed by the sender number and confirmation must come from the same sender.

Production recommendation: use a dedicated low-balance launcher wallet, an Upstash Redis database for state, and an allowlist while testing. Never reuse a treasury wallet or expose its key client-side.

Robinhood Chain + Pons v2

The integration targets Robinhood Chain (chain ID 4663) and the active Pons v2 launch factory configured in .env.example. The service reads canLaunch, the selected config, current economics, and launch fee immediately before deployment.

Pons v2 currently documents a launch gate, so the configured launcher wallet must be approved while public launches are closed.
